# 工具调用为什么需要统一治理

这份笔记保留既有工具设计的工程取舍；完整契约见 [工具治理](../architecture.md#工具治理)。

工具名、参数 schema 和 handler 只是执行的开始。实际调用还需要可信授权、次数与分类额度、共享截止时间、取消，以及成功结果如何计入观察和来源。如果普通工具、官方文件工具和第三方原生工具各走一条路径，很容易在重试或恢复时漏掉这些限制。

普通工具经 `ToolExecutor` 执行，社区原生工具保留上游实现并经 `NativeToolGovernance` 接入。选择与授权仍分别维护：模型看得到某个工具，不意味着这次具体参数已经获准执行。

重试采用明确的只读协议。调用者不能仅凭错误文本或 `retryable` 标签推断安全；每次尝试重新授权并共享原截止时间，handler 成功后出现的结果投影或提交失败不会再执行 handler。逻辑调用、额外重试预留与真实已知执行次数分开计量，避免用一个数字掩盖成本和副作用的不确定性。
