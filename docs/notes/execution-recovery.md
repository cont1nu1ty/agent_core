# checkpoint 恢复为什么不能等同于恰好一次执行

这份笔记整理既有故障恢复设计；运行契约统一维护在 [checkpoint 与恢复](../architecture.md#checkpoint-与恢复)。

checkpoint 可以保存图进度、预算和已完成调用，但外部工具写入与保存 checkpoint 通常不是同一个事务。工具已经写入、进程却在提交结果之前崩溃时，恢复状态可能仍显示该调用未完成。直接重放存在重复副作用，跳过又可能丢失结果。

因此恢复先核验身份、状态版本和精确指针，再保留已经消耗的额度与完成事实。缺失 checkpoint 明确失败；已成功的 pending writes 通过官方状态 API 合并。重试协议下结果未确认的调用保留未知状态和消耗，不能伪装成成功或获得新的预算。

写入工具还需要自己的幂等键、结果核验或补偿。相同 Run 的恢复与同 Task 开始新 Run 也要分清：前者继续执行账本，后者只继承允许的文档与计划事实。内存 Saver 和 Fake 故障注入能够验证这些契约，真实数据库提交、并发和跨进程窗口需要单独实验。
