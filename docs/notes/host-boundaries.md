# 为什么把宿主与内核分开

这份笔记从既有工程的核心边界设计整理而来；实际接入契约统一维护在 [核心架构](../architecture.md#宿主与内核边界)。

一次 Agent Run 需要模型、工具、预算、取消与执行状态，但它不应自行决定用户身份、业务权限、数据库连接或任务归属。把这些资源交给宿主显式注入，能让相同执行机制用于不同应用，而不把某个领域的配置和 DTO 带进通用 API。

因此 `AgentService` 只接收工厂、注册表与资源，`WorkflowDefinition` 决定图的构建，`RunContext` 提供可信控制与上下文。领域提示、引用投影、用户确认和公开 payload 白名单在宿主边界完成。

独立包边界还需要可执行证据：仅把源码移入新目录并不够。`check_core.py` 禁止宿主与业务数据库客户端导入，并拒绝网络、SQLite 和子进程 I/O；wheel 模式在仓库外导入构建产物。它验证核心契约能独立运行，仍不能替代真实宿主接入与服务验收。
