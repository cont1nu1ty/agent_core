# 可交互的计划执行

本页保留既有计划设计中的通用契约。实现入口为 [planning/plan_execute](../src/agent_core/planning/plan_execute/)，核心调用边界见 [架构](architecture.md)。

## 流程与确认

`start_plan` 明确创建独立计划实例与预算窗口。探索仅使用宿主显式提供的只读工具子集；缺少影响目标、范围、步骤或验收的信息时返回问题，信息充分时形成计划预览。

预览包含目标、范围、约束、步骤、预期证据与验收项。回答问题不等于执行确认；执行动作须绑定具体计划 ID 与 revision。补充或修改推进原计划版本，旧版本不能确认执行更新后的计划。

确认后，整份计划交给现有 ReAct agent。外层不逐步另写模型/工具循环；ReAct 返回后形成 `ExecutionReport`，登记步骤结果、来源、失败与缺项。确定性检查先核对步骤及证据，再用官方 `RubricMiddleware` 评价最终产物。需要新增工作时仅在已确认范围内修订未完成步骤。

| 阶段/产物 | 含义 |
| --- | --- |
| `clarifying` / `questions` | 等待关键信息 |
| `ready` / `plan_preview` | 已有计划，等待明确确认 |
| `executing` | 执行、检查或范围内重规划 |
| `completed` / `final_result` | 通过步骤检查和最终评价 |
| `partial` / `failed` / `cancelled` | 未全部验收或运行未完成 |

成功生成问题或预览，只表示本 Run 成功产生交互产物，不表示整个任务完成。Todo 和工具事件表示进度，不能替代计划验收。模型复核也不等于独立事实验证。

## 状态、预算与恢复

`plan_state` 保存于官方 root checkpoint，包含版本、确认边界、步骤事实与计划级预算；宿主保存精确指针并提供公开读投影，不建立竞争的计划正文状态。

默认最多 8 个步骤、3 次自动重规划、3 轮最终评价和 64 次模型调用。所有阶段、结构化修正、grader 与用户后续交互共享计划预算。修改原计划、新建后续 Run 和同 Run 恢复都不能刷新额度。明确 `start_plan` 建立新窗口，但该 Run 再次恢复仍保留已经消费的额度。

同 Run 恢复继续保存进度；同 Task 的新 Run 继承允许的计划文档、确认状态、完成事实、来源与累计预算。未知副作用保留“结果未确认”，须先核验。失败收尾保存已消费额度，不因取消或局部失败退款。

## 结构化阶段

`explore/report/replan` 使用独立结构化提示与 `ToolStrategy`。普通文本或空响应不能视为 schema 成功；通过官方 middleware 的 `after_model/jump_to` 最多追加两次缺失结果修正，次数随 checkpoint 保存，所有请求仍计入统一预算。

报告须覆盖准确的步骤 ID，不能漏报、多报、重写已完成事实或仅凭 Todo 宣称完成。报告修正期间禁用业务查询，避免为补格式重复执行工具。Rubric 的格式循环由官方组件负责，并受共享模型总预算约束；失败、grader 错误或达到评价上限不能映射为完成。

确认边界对目标、范围、约束和验收字段提供确定性保护，不能证明任意自然语言约束的语义满足。步骤提示与宿主的实际工具授权仍共同承担执行限制。完整交互 UI、业务幂等和队列认领属于接入应用。
